## Цель

Всё взаимодействие заказчика с ASF — в **полноэкранном Telegram Mini App** (UI на русском). Чат с ботом — только вход и уведомления.

## Поверхности

| Поверхность | Роль |
|-------------|------|
| DM с ботом | Онбординг `/start` (RU), Menu Button / кнопка WebApp, push-уведомления |
| Mini App (fullscreen) | Home-действия, список проектов, workspace проекта (Discovery / правки / замечания к реализации) |
| Owner HITL (бот) | `/review`, `/approve`, `/changes`, `/reject`, `/plan`, `/export` (MVP) |

На телефоне Mini App вызывает `Telegram.WebApp.expand()` и `requestFullscreen()` (Bot API 8.0), чтобы занять весь экран, с отступами `safeAreaInset` / `contentSafeAreaInset`. Вёрстка компактная: home в один экран; workspace — колонка (лента скроллится, поле ввода занимает **20–25%** рабочей области, кнопки Файл / Голос / Отправить внутри него). Компактный **Experience Layer**-маскот стоит в шапке workspace (не в поле ввода): Rive, если есть `mascot.riv`, иначе SVG-компаньон в золоте/cyan. Варианты ответа открываются **попапом** «Варианты ответа», а не чипами в чате. Новый проект начинается с **приветственного попапа** («Поехали»); вопросы ТЗ — после него. Один `expand()` только растягивает нижнюю шторку — из‑за этого старые сборки не помещались на экран.

## Почему не отдельный Telegram-чат на проект

У бота **один** личный чат с пользователем. Bot API не умеет открыть второй DM «под этот проект».

**Чат проекта** в ASF = **project workspace** в Mini App (лента + контекст `project_id`). Forum topics / отдельные Telegram-чаты — Future.

## Home (после онбординга)

Кратко: идея → Discovery → черновик ТЗ → ревью владельца → **смета клиенту** → задачи → простой MVP.

Три действия:

1. **Создать проект**
2. **Изменить проект**
3. **Замечания к реализации**

### Создать проект

1. Создать `project` для этого Telegram-пользователя.
2. Открыть workspace проекта в Mini App.
3. Discovery (текст, **попап вариантов** и/или голос). После создания — попап, что будет происходить; «Поехали» запускает первый вопрос ТЗ. Следующая реплика ассистента — **только следующий вопрос** (без «уже зафиксировали»; варианты в «Варианты ответа», не в ленте). В Telegram голос **записывается в Mini App и уходит в Groq Whisper** (`POST /stt/transcribe`); Web Speech в WebView Telegram не используется — он часто «слушает» без текста. Вне Telegram (smoke в браузере с `?uid=`) Web Speech ещё можно. Транскрипт вставляется в поле ответа, дальше тот же ingest, что у текста. Интервью закрывает разделы ТЗ, пока заказчик не поставит паузу, не передаст оставшееся разработчику или не напишет «готово» после покрытия и финального прохода (дополнения, сумма, файл постановки). В чате проекта — **полоса прогресса** (серый фон, зелёная заливка); подпись — **процент** или «ещё пара уточнений», не «N из M» как анкета (DEC-014). После отправки в рабочем пространстве можно скачать тот же черновик ТЗ.
4. Бот может уведомить, когда нужно ответить или когда ТЗ ушло владельцу.
5. После approve черновика ТЗ в workspace появляется **карточка сметы** (вилка рынка, «почему столько стоит», дисклеймер). Кнопки: **Подтверждаю** / **Нужно обсудить**. Planner стартует только после подтверждения ([DEC-012](../../decisions/DEC-012-Client-Market-Estimate.md)).

### Изменить проект

1. Показать список проектов пользователя.
2. Выбор проекта.
3. Workspace в режиме **change**: уточнения → обновление KG, проверка gaps / противоречий, возможный возврат стадий Discovery или эскалация владельцу.

### Замечания к реализации

1. Список проектов, по которым можно оставлять замечания (после доставки / ознакомления с MVP).
2. Выбор проекта и текст/голос замечания.
3. Классификация: дефект / изменение / новое требование.
4. Проверка против утверждённого ТЗ / KG; при противоречии или блокирующей неоднозначности → `HumanDecisionRequired` / путь владельца.
5. Сохранение как сущности/связи (не терять в свободном чате).

## Experience Layer (маскот)

Клиентский компаньон интервью (DEC-011). **Не** меняет контракты Discovery и HTTP.

| Событие | Когда |
|---------|-------|
| `idle` | Workspace готов; возврат на home |
| `listening` | Идёт запись голоса |
| `thinking` | Отправка / STT / загрузка workspace |
| `got_answer` | Текст (или вариант) заказчика принят |
| `got_voice` | Транскрипт вставлен в поле ответа |
| `got_file` | Файл успешно принят |
| `draft_ready` | Показана полоса скачивания ТЗ |
| `error` | Ошибка запроса / микрофона / STT |

**Спокойный режим:** кнопка **«Спокойный режим»** пишется в `localStorage` (`asf-calm-mode`). `prefers-reduced-motion` замораживает или скрывает маскота и foundry-фон; текст статуса остаётся. Замена placeholder: положить `apps/miniapp/mascot.riv` (state machine `Mascot`, входы как имена событий). См. `apps/miniapp/README.md`. Lip-sync / рот под TTS — Future.

## Язык

- UI заказчика и тексты бота: **русский**
- Канон KG и рассуждения агентов: **английский** (Language Normalizer — инфраструктура)

## Переходные команды бота

Пока Mini App не поставлен, заказчик может пользоваться `/new`, `/use`, текстом/голосом в DM. Пути совместимы с `core.services`. После появления Mini App — приоритет у него.

## Уведомления (DM бота)

Примеры: нужен ответ в Discovery; черновик ТЗ у владельца; владелец запросил правки; **смета готова / подтверждена / нужно обсудить**; MVP / экспорт готов. По возможности deep-link / WebApp открывает нужный project workspace.
