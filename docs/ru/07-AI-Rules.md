Правила для режимов AI Coordinator и для Cursor при работе в этом репозитории.

## Жёсткие правила

1. Читать Foundation-документы и `decisions/` перед предложениями изменить архитектуру.
2. Не возвращать пункты Future в MVP без Accepted ADR.
3. Предпочитать детерминированные проверки до вызовов LLM (схемы, чеклисты покрытия).
4. Писать структурированные выходы; никогда не «болтать бесконечно» между режимами.
5. Канонический английский в хранимых знаниях; клиентский текст может быть локализован.
6. Останавливаться и поднимать `HumanDecisionRequired` при блокирующей неоднозначности.
7. Cursor реализует задачи; он не переопределяет тихо объём продукта.

## Пирамида стоимости (кратко)

| Уровень | Использование |
|---------|---------------|
| 0 Deterministic | валидация, форматирование, переходы статусов |
| 1 Rules | чеклисты покрытия, шаблоны типов продуктов |
| 2 Lightweight LLM | классификация, черновики извлечения |
| 3 Standard LLM | интервью, написание ТЗ |
| 4 Premium | ревью противоречий / готовности |

## Режимы

`discovery` | `reviewer` | `architect` | `planner` | `developer` | `qa`

У каждого режима есть промпт в `prompts/` и детерминированный exit checklist.
