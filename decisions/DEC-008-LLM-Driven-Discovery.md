# DEC-008 — LLM-driven Discovery interview

| Field | Value |
|-------|-------|
| Status | Accepted |
| Date | 2026-08-28 |

## Context

The deterministic Discovery FSM (`discovery/interview.py` + the static catalog in
`discovery/tz_outline.py`) produced a rigid, form-like interview: fixed question
text, fixed choice chips, regex answer matching, one topic per message. Customers
rated it worse than an unstructured ChatGPT session, even though raw chat omits
implicit requirements and asks redundant questions (cf. OntoAgent, arXiv
2605.05828: checklist-guided LLM interviews beat free chat on requirement
recall).

EPIC-02 originally fixed "deterministic Discovery owns stage/topic advances and
KG writes; the LLM only adapts the outline". That note is superseded for turn
orchestration by this ADR.

## Decision

The **LLM drives the customer-facing turn** (`DISCOVERY_ENGINE=llm`, default
`auto` = llm whenever `LLM_PROVIDER` is not `stub`):

- Per customer message the interviewer LLM receives the adapted outline as a
  coverage checklist (per-topic status + captured summaries), the recent
  transcript, and the quality-floor state. It returns JSON: `reply_to_customer`,
  `captured` topic updates (canonical English summaries), contextual `chips`,
  and `next_action` (`continue | review | ready_for_owner | pause`).
- The LLM chooses what to ask next and how to phrase it, may follow up on a
  vague answer, and may answer customer counter-questions.

The **deterministic core keeps the guarantees** (unchanged):

- KG writes stay in code (`Requirement` / `OpenQuestion` / `Risk`); unknown or
  invented topic ids from the LLM are dropped.
- Coverage gate: `ready_for_owner` executes only when the adapted outline has no
  remaining topics and the quality floor passes; otherwise the turn is forced
  to continue. The customer-facing override must **not** list catalog
  `title_ru` — see [DEC-014](DEC-014-Customer-Never-Sees-Catalog-Menu.md).
- Quality floor (`discovery/quality.py`), clarify quota, outline adaptation
  (`discovery/adapt.py`), draft TZ emission, and the owner HITL gate are
  unchanged.
- Pause / resume / «готово» / «остальное с разработчиком» intents are matched
  deterministically before the LLM call.
- Choice chips are generated by the LLM per turn and sanitized in code (max 5,
  label length cap, the exclusive «discuss with developer» chip is always
  appended by code).
- Any LLM failure or invalid JSON falls back to the deterministic FSM turn, so
  the customer always gets an answer. Tests run on stub/fake providers and keep
  exercising the FSM path.

## Consequences

- The interview feels like a guided conversation while TZ coverage stays
  guaranteed; the outline remains the advantage over free-form chat and
  stays **internal** (DEC-014).
- `prompts/discovery-interview.md` is the interviewer prompt;
  `prompts/discovery.md` is retired.
- One LLM call per customer turn adds ~1–4 s latency and token cost; the
  transcript window and checklist size are bounded.
- Model quality bounds phrasing quality; `LLM_MODEL` remains configurable.
